# GenBI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在本仓落地 GenBI：数据源（对齐 tiga 外连能力）、完整建模/部署/Wren ask、虚拟服务器多选数据源与「组×源」共用 ACL，对外工具 `{system.code}_ask_bi`。

**Architecture:** 新建 `backend/app/modules/genbi/`（连接、项目、MDL、部署、ACL 改写、ask）。`mcp_gateway` 扩展组–数据源关联与 runtime 工具。向量索引写入现有 PostgreSQL（pgvector）。应用库不做 MySQL `DATABASE_TYPE`。外连类型对齐 tiga-case。

**Tech Stack:** FastAPI、SQLAlchemy 2、Alembic、Redis、Vue/Element Plus、Wren AI、ibis、sqlglot；参考 `/Users/v/Documents/code/cloudladder/tiga-case`。

## Global Constraints

- 应用库：仅 PostgreSQL（`.env` `DATABASE_TYPE` 不做 MySQL）。
- 向量：现有 PG + pgvector，不新增独立向量库配置。
- GenBI **外连**类型对齐 tiga-case（含 MySQL 等业务库）。
- ACL 挂「虚拟服务器 × 数据源」；组内所有调用者共用；不按人拆。
- 工具名默认 `{biz_system.code}_ask_bi`；重名走 v1 别名。
- 未成功部署不可 ask；不走业务 REST token 刷新。
- 调用日志记 ask_bi；默认不落 SQL/结果集明文。
- 管理权限 `module_genbi:*`；业务用户不能进 GenBI 后台。
- 密码等密钥用 `CryptoUtil` 加密；中文错误信息。
